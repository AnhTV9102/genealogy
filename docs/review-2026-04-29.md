# Project Review — 2026-04-29

## Scope
- Reviewed project structure, Gradle build, layering, API controllers, and key application services.
- Performed a build/test check attempt in this environment.

## What is good
1. **Clean layered architecture direction**
   - Clear separation between `api`, `application`, `domain`, and `infrastructure` packages.
2. **Reasonable baseline quality tooling**
   - Spotless + Checkstyle + PMD configured in Gradle.
3. **Database migration discipline**
   - Flyway migration path is configured and schema is versioned.
4. **Domain-focused services**
   - `PersonService` and `RelationshipService` keep orchestration logic centralized.

## Key risks and gaps

### 1) Security is not actually enabled
- Security dependencies for Spring Security are currently commented out in `build.gradle.kts`.
- JWT properties are present in configuration, but there is no active security pipeline visible from current build/runtime wiring.
- **Risk:** APIs appear effectively open unless protected elsewhere.

### 2) Invalid enum input can leak as 500 errors
- `Gender.valueOf(request.gender().toUpperCase())` and `RelationshipType.valueOf(request.type().toUpperCase())` can throw `IllegalArgumentException` for malformed input.
- **Risk:** Client validation errors may surface as internal errors instead of consistent 4xx business errors.

### 3) N+1 query pattern in relationship traversal responses
- `getParents`, `getChildren`, `getAncestors`, and `getDescendants` repeatedly call `personRepository.findById(...)` inside stream pipelines.
- **Risk:** Performance degradation on larger family graphs.

### 4) API style inconsistency and overlap
- Relationship endpoints are split across `/api/v1/relationships/*` and `/api/v1/persons/{id}/*` across two controllers.
- **Risk:** harder API discoverability and maintenance due to mixed ownership.

### 5) No active test dependencies in Gradle
- Test dependencies appear commented out in `build.gradle.kts`.
- **Risk:** low confidence for refactors and regression prevention.

## Prioritized recommendations

### High priority
1. Enable Spring Security dependencies and wire JWT authn/authz filter chain.
2. Add request-level validation/mapping for enum fields with explicit error messages.
3. Restore test dependencies and add at least:
   - Service unit tests for person/relationship flows.
   - Controller slice tests for validation and status codes.

### Medium priority
1. Remove N+1 patterns by loading persons in batch (`findAllById`) and mapping in-memory.
2. Normalize API surface ownership (decide one controller pattern for relationship-derived resources).

### Low priority
1. Add API standards for pagination/sorting/default limits on list endpoints.
2. Expand operational readiness: add readiness/liveness endpoint conventions and basic dashboards/alerts.
